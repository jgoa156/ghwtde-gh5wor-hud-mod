# HUD fixes plugin (`wor_hud_fixes.asi`): reverse-engineering notes

Ultimate ASI Loader v9.7.4 (`dinput8.dll`, x86; the game imports DINPUT8.dll) loads `wor_hud_fixes.asi` from the game
folder. In-memory patches only; every patch site is byte-checked (`kSites` in `plugin/src/wor_hud_fixes.cpp`) and
the plugin stays inert on any mismatch. Log: `<game>\wor_hud_fixes.log`. Game: GHWT_Definitive.exe (GHWT:DE 1.4.3.5,
image base 0x400000, PE timestamp 0x562b029a). `plugin/src/names.h` is generated by `tools/gen_plugin_names.py`
(texture checksums + star power geometry from `tools/wor_1g.py`), so the HUD and the plugin can't drift apart.

## Engine facts

- **Texture names**: a sprite's texture checksum lives at `[element+0x214]` (also its `texture` property, see
  GetProperties 0x59df10). **SetTexture 0x59e6d0** (thiscall, checksum) stores it and looks the texture up by name
  (0x4fad90 on [0xd4e3c8]): the most recently loaded texture with that name wins, which is why the stock
  `z_in_game` textures (reloaded every song) shadow ours from the 2nd song on. Fix pattern: our own unique names.
- **Element fields** (CScreenElement): pos 0xa8/0xac, scale 0xc0/0xc4, dims 0x1bc/0x1c0, z 0x1c8, parent 0x64.
  Setters (thiscall, callee cleans): **SetPos 0x5a0fd0** (x, y, int), **SetScale 0x5a17e0** (x, y, int, int),
  **SetDims 0x5a14e0** (w, h). Children of a container / window are placed relative to its top-left corner.
- **Element lookup** 0x5f6160 (child by id, weak-ref out params) is hooked by the DE (its prologue jumps into the
  DE): avoided; the plugin reaches our clip window through a segment's parent pointer instead.
- **Pak residency**: theme and gem paks stay on their pak-manager maps between songs ("already loaded. Adding
  handle"); `hudtheme_unload_paks` only releases handles. Theme structs only carry a `pak` field (no per-song hook).

## 1. Note-streak lights (`senotestreaklights`, QB 36c22211)

Class vtable 0xa11e98: `[0x476580 type id, 0x476930 dtor, 0x476c30 init, 0x476700 on_value]`.
- init 0x476c30: desc_id -> [w+8], player -> [w+0xc], `bulb_textures` (c05f18e6) CArray at [w+0x10] ([w+0x14] count,
  [w+0x18] data), `bulb_props` (0x88bacaf1) -> five light elements at [w+0x1c..0x2c]; [w+0x30] ok, [w+0x34] last streak.
- set_lights 0x476590(streak): mult = thunk 0x42be60(player-1, 1) (ecx = [0xc0c770]); star power = thunk 0x4649d0
  (player-1) (ecx = [0xc0d77c]); both thunks jump into the DE's section, so they are called, never inlined. Stock set
  choice: SP -> blue, mult > 3 -> purple, == 3 -> green, else base (x1 and x2 share it). Marks c = streak % 10 (10
  for positive multiples, streak clamped to 30); full = int(c * 0.5 [0xa0f028]), half = full + (c & 1).
- Plugin: detour of set_lights for widgets whose first light element's texture is one of ours (the desc starts it on
  `WoR_HUD_light_0`); WoR's mapping x1 pink, x2 orange, x3 green, x4 purple, SP blue, `WoR_HUD_light_*` names.
  WoR's colours (hud_widgets `combolights` led_colors): x1 (255,180,180), x2 (243,169,64), x3 (128,236,68),
  x4 (175,101,238). Pink set = GH3:WoR base lights luminance-tinted with x1's colour (user OK).

## 2. Star power tube widget (update 0x478630, thiscall (value*, event*), ret 8)

- [w+0xc]/[w+0x10] value range (0..100), [w+0x1c]/[w+0x20] vector of the six segment elements, [w+0x14] player,
  [w+0x28] band flag. value = `**(float**)value`; event `[+4] == 0x8683400c` is a texture-only refresh.
- Charged flag: SP >= 50.0 ([0xa10548]) or active -> texture `hud_rock_tube_glow_full_b` (= 0x20273d7b + 0xea155069),
  else `hud_rock_tube_glow_full`; set with two SetTexture calls (0x4786f5, 0x47877f). Per segment then SetScale(0.3,
  0.3 * fill_i) (0x4787ff).
- Plugin 1.1: those two calls go through a wrapper that swaps the stock names for `WoR_HUD_spseg` / `_b` on our
  segments. Plugin 1.3: after the update, segments 1-5 are scaled to 0, segment 0 becomes `WoR_HUD_spfull` / `_b`
  (glass-shaped, full length, drawn with the tube's transform) and its parent window `sp_clip` is resized so its top
  edge is the charge level (0-50%: fill bottom -> half divider y 528; 50-100%: -> top). Without the plugin the window
  is static and the six segments work as before.

## 3. Theme switch crash (DE bug), plugin 1.2

Dumps: first-chance AV at 0x6403d0 reading past the font table, then 0xc00001a5. 0x6403b0 = font unload (cdecl,
checksum; here `WoR_HUD_num_a1`, our numeral font in the theme pak). In memory the DE had patched the loop end to
its enlarged table (0x63001e98) but the start was still 0xeecd60, so a font outside the first 32 slots ran into
unmapped memory. Stock themes ship no fonts in their paks. The plugin copies the font-add loop's bounds (0x64072f /
0x640743) into the unload loop (0x6403c9 / 0x640417 / 0x64041e, end 0x6403dc) on first use and logs both. Fallback if
that fails: ship no font. Tools: `tools/dump_info.py`, `tools/dump_mem.py`.
